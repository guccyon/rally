# C-0015: PR 本文の「背景」「問題」の欠けが、検査・判定を 2 往復させ、判定が reject から adopt に逆転して差し戻しになった（PR #1113、Issue #1047、job 5480）

- 出来事の種類: 差し戻し
- 分析の記録: 制御プレーンの events `case.analyzed`（id 1004155）。事例型の分析役（Engine ADR 0023）
- 対象: PR #1113（Issue #1047、実装 job 5480）。検査 job 5481・5487、判定 job 5486・5488、本文の直し job 5489
- 記録日: 2026-11-13
- 知見: K-0033（テーマ 4）、K-0034（テーマ 6）、K-0035（テーマ 6）
- 材料: case.analyzed の分析だけ。session.txt と handoff の中身は見ておらず、実装役がテンプレートを開いたか、head を動かした主体が誰かは分析役の推測のまま

## 出来事

- 中身（ワークフローのひな形の直し、head-record.mjs、K-0004 の追記）では、裁かれた 3 件の仮決めがすべて採用された。差し戻された理由は PR 本文の見出しの構成だけ
- 実装役が PR テンプレートの「## 背景」「## 問題」を落とし、背景と問題を「## 概要」に詰め込んだ
- 検査役（job 5481・5487）は 2 回とも OV-001（shadow）と PR-002 で同じ点を指摘した
- 判定役の 1 回目（job 5486、10:59 から 11:00）は、古い head 7535fd を対象に、「中身は概要の中で順に読める」として 2 件とも reject した。10:59:30 に head が 7535fd から 277231 に変わっており、job 5486 は 10:59:46 に積まれていた
- 判定役の 2 回目（job 5488、head 277231）は同じ指摘を adopt した。本文の直し（job 5489）のあと、6 秒後の 11:03:13 にマージが決まった。直した本文は検査をもう一度通っていない
- 実害はない。ただし、本文の型を作る段階で防げた指摘が検査と判定を 2 往復させ、判定役の結論が往復の間で逆になった

## 観点ごとのなぜなぜ

### communication（確からしさ mid）

1. なぜ: 実装役の PR 本文に「## 背景」「## 問題」がなく、両方の中身が「## 概要」に入っていた
2. なぜ: 実装役がハンドオフの summary.md（概要・対応内容・影響範囲・互換性・動作確認・補足・仮決め・知見）をそのまま PR 本文にしていた
3. なぜ: 実装役が PR テンプレートを開いた形跡は会話にない。ハンドオフの書式とテンプレートが別のものとして扱われ、両者の対応が実装役に渡っていなかった
4. なぜ: 「背景・問題は変更に必要なときに書く」という条件の線は、検査役の PR-002 の中にだけあり、実装役への指示には同じ言葉で渡っていなかった（推測）
5. なぜ: 実装役は「概要に経緯を書けば足りる」と判断し、検査役は「見出しを削った」と判断した。同じ本文が役割ごとに違う基準で読まれた

- 真因: 実装役が書く summary.md の書式と、検査役が照らす PR テンプレートの見出しが揃っていない。どの変更で「背景」「問題」が要るかの基準も、実装役に伝わっていない

### inspection（確からしさ high）

1. なぜ: 見出しの欠けは検査（job 5481・5487）で 2 回とも見つかったが、1 回目の判定（job 5486）で reject され、本文は直らなかった
2. なぜ: 1 回目の判定役は、OV-001 が shadow で rubric の本文も渡されておらず照らせないこと、中身は概要の中で順に読めることを理由に、重さをワーニングとした
3. なぜ: 2 回目の判定役は同じ指摘を「変更に必要な見出しを削った、機械的に直せる」と読んで adopt した。PR-002 の基準の解釈が判定ごとに揺れた
4. なぜ: 判定役に rubric の本文が渡らず、「必要な見出し」の判断が判定ごとの解釈に任されていたため
5. なぜ: さらに前の段では、本文を作るときにテンプレートの見出しと突き合わせる機械的な検査がなく、PR を出す前に止まらなかった

- 真因: PR 本文の見出しの欠けを PR を出す前に機械で止める検査がない。判定役には rubric の本文が渡らず、同じ指摘への裁きが reject から adopt に逆転した

### process（確からしさ mid）

1. なぜ: 検査と判定が 2 往復し、2 回目でやっと本文の直し（body_fix）が出た
2. なぜ: 10:59:30 に head が 7535fd から 277231 に変わったのに、1 回目の判定（job 5486、10:59:46 に積まれた）は古い head 7535fd を対象に行われた
3. なぜ: head を変えた主体は記録にない。committee（job 5483、10:57:33 に積まれた）が押したと推測されるが、5483 の開始・終了のイベントがない。古い head の判定を取り消して待つ仕組みもなかった
4. なぜ: body_fix（job 5489）で本文を直した 6 秒後の 11:03:13 にマージが決まった。直した本文は検査をもう一度通っていない

- 真因: head が更新されても、古い head に対する判定がそのまま走る。誰が head を動かしたかが記録に残らず、検査と判定がやり直しになった。本文の直しの後に本文を検査し直す段もない

## 真因

- 実装役が書くハンドオフの本文の書式（summary.md）と、検査役が照らす PR テンプレートの見出し（背景・問題）が揃っていない。PR を出す前に機械で突き合わせる段もない
- 判定役に rubric（OV-001・PR-002）の本文が渡らず、「変更に必要な見出し」の判断が判定ごとの解釈に任されていた。そのため、同じ指摘への裁きが reject から adopt に逆転した
- head が更新されても、古い head に対する判定が取り消されずに走った。head を動かした主体の記録も欠けていて、検査と判定が 2 往復した

## 学び

1. テーマ 4（役割間の言葉と伝達）: 実装役が書く本文の書式と、検査役が照らすテンプレートが別々に定義されていると、同じ本文が役割ごとに違う基準で読まれる → K-0033
2. テーマ 6（工程の進め方）: head が変わったあとに古い head を判定すると、判定が無駄になり往復が増える → K-0034
3. テーマ 6（工程の進め方）: 本文の直しのあとに検査を通さずにマージすると、直した結果の正しさが確かめられない → K-0035
