# evals/

この製品の Golden Set とルール検証。汎用部分は Engine の `eval-corpus/` に置き、ここは差分だけを持つ。

- `golden/`: ペア比較形式の採点。1 件ごとに「どちらが望ましいか」と採点理由 1 行を残す。正例・負例を 1:1 に近づけ、負例には意図的なアンチパターンを含める
- 評価仕様は Engine の `definitions/evalspec.yaml`（`l4-pairwise`）
- P0b の目標は 30 件（pr-merge-criteria の判断の記録 3 件を含む）。30 件は初期試行で、自動差し戻しの解放条件ではない

## 採点の軸（2026-10-29 方針 A）

ペア比較は「成果物として正しいか」で採点する。負例はコード 1 行だけを変え、同じ差分の契約・試験・説明は元のまま残すので、負例の差分は中で食い違った成果物になる。人が製品の振る舞いとして「欠陥でない」と判断した組（0005・0011・0014・0015・0022・0024・0028・0029・0033）も、成果物としては元（b）を望ましいとし、製品の判断は `product_judgment: tie` に残した。製品の判断は仕様への差し戻し（契約や仕様を変えるチケット）として扱う。

- 引き分け（`preferred: tie`）は、両方とも中で筋の通った成果物で、差が重さの物差しのワーニングだけのとき（0002・0003）
- 判定器は core-gates/severity.md（重さの物差しと「利用者の利益で裁く」姿勢）を読む。成果物の正しさと製品の判断が分かれるときの扱いは Tetsuro に確認中（仮決め A）
