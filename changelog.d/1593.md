### 追加
- アクセストークンを署名付きにできるようにした: backend の起動時に環境変数 `ACCESS_TOKEN_SIGNING_KEY`（32 バイト以上の秘密の鍵）があれば、本部・コーチ・生徒のトークンを HMAC-SHA256 の署名付き（`v1.<役割>.<アカウント ID>.<署名>`）で発行・検証し、手で作った `mock.<役割>.<ID>` のトークンや役割・ID を書き換えたトークンは 401 にする。生徒に見えるコーチの ID からコーチになりすます・任意の ID で本部の操作を読むことを、実利用者が入る前に塞ぐため。鍵がなければ今までどおり署名なしのモックで動く。契約（`bearerAuth` の不透明なトークン）と DB は変えない。鍵の配り方は人が用意する（#1593）
- staging でトークンを作る `access-token`（backend のイメージに同梱。`--hints` で本部 1 人とコーチ 3 人の手がかり、`--account <ID>` で 1 人分）。触れる環境のログインの手がかり（`.factory-config/ship.yaml` の `touch.accounts`）はこれで作るようにし、鍵を入れても QA が今までどおりログインできる。手順は `apps/backend/README.md` の「staging でトークンを作る」（#1593）
