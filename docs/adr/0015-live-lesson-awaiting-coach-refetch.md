# ADR 0015: 待機表示から通話中への切り替えは取り直しで知る

- 状態: 提案（工場）（2026-11-16、Issue #1697。もとは #1654）
- 関係: ADR 0010（生徒アプリの表示はサーバーの状態から出す）、`specs/contracts/api/student-app/openapi.yaml` の `getLiveLessonSession`・`LiveLessonSession` の `coach_joined_at`・`bookings[].student_joined_at`（#1696）、glossary の `live_lesson_session`、`specs/stories/student-prejoin-check.yaml` の step 6

## 文脈

生徒が入室（`startLiveLessonSession`）すると、コーチがまだ入っていなくても生徒アプリのビデオ通話の画面に「コーチと通話中です」と出ていた（#1654）。アプリはセッションが通話中（`in_progress`）かどうかだけで表示を決めており、コーチが入室したかを知る手段がなかった。

#1696 で、セッションに参加者ごとの最初の入室の時刻（コーチは `coach_joined_at`、生徒は予約ごとの `student_joined_at`）を残し、参加者がセッションの今の状態を読む `getLiveLessonSession` を足した。入室は `startLiveLessonSession` を呼んだ時刻で記録され、入り直しても最初の時刻のまま変わらない。生徒アプリはこれを使って、コーチの入室の前と後で表示を分ける。

## 決定

1. **通話中（`status` が `in_progress`）で `coach_joined_at` が null のあいだを「コーチの入室待ち」とする**（`LiveLessonSession.awaitingCoach`）。ビデオ通話の画面の映像の欄は、入室待ちなら「コーチを待っています」、そうでない通話中なら今までどおり「コーチと通話中です」を出す。コーチが先に入室していれば、入室の応答の時点で `coach_joined_at` があるので最初から通話中になる
2. **入室待ちのあいだだけ、一定の間隔で `getLiveLessonSession` を取り直す**。間隔は生徒アプリの `liveLessonAwaitingCoachRefetchInterval`（`state/student_flow.dart`、5 秒）の 1 か所で決める。応答を受けてから次の取り直しを決めるので取り直しは重ならない
3. **入室待ちでなくなったら取り直しをやめる**。コーチの入室を知ったとき・通話を終了したとき・持っているセッションが替わったとき・状態を捨てたとき（ほかのタブでのログアウトなど）
4. **取り直しの失敗は画面に出さない**。待機の表示のまま、次の間隔でまた取り直す（通話の操作の失敗の文言も消さない）
5. `coach_joined_at` が応答に載っていないときは null と同じに扱う（契約の「null か載らない」に従う）

## 結果

- コーチの入室前は待機、入室後は「コーチと通話中です」と、サーバーの記録に合った表示になる
- 待機のあいだだけ通信が増える（間隔ごとに 1 回）。コーチの入室を知るのは取り直しの間隔ぶん遅れることがある。間隔は定数 1 か所で調整できる
- 入室の記録を返さないサーバーにつないだときは、コーチが入っていても待機のまま変わらない（#1696 と一緒に出す前提）
- 通話そのものの接続処理（モックの通話サービス）は変えない

## とらなかった案

- **通話中のあいだずっと取り直す**: コーチの入室後や通話の終了後にも通信が続く。今の目的（コーチの入室を知る）には待機のあいだで足りる
- **push 通知や境界間イベントで即時に知らせる**: 生徒アプリに常時のつながり（WebSocket など）や push の受け口がなく、仕組みを足す手間が大きい。切り替えが数秒遅れても困らない
