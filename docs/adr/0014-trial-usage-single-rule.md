# ADR 0014: 体験の使用済み判定をサーバーの 1 つの規則にする

- 状態: 提案（工場）（2026-11-15、Issue #1658。もとは #1653）
- 関係: ADR 0003（層。domain の規則・application の照会・interface の写像）、ADR 0004（DB の変更はしない・既存データはさかのぼらない）、ADR 0005（ビデオ通話の枠の消費は変えない）、ADR 0006（完了したレッスンはサーバーの記録に従う）、ADR 0010（生徒アプリの次の操作はサーバーの状態から）、`specs/contracts/api/student-app/openapi.yaml` の `createBooking`・`listMyBookings` の `trial_available`・`submitVideo`

## 文脈

体験（月額契約の前に無料で受けられる、通話か動画添削のどちらか 1 回）を使ったかの判定が予約の集約（`Booking::is_trial_available`）にしかなく、動画の送付はこの判定を呼ばず、アプリも予約の件数で数え直していた。そのため、体験の通話を受け終えた未契約の生徒がそのあと無料で動画の添削も依頼でき（#1653）、添削のあとにも体験予約ができた（#1595・#1645）。

## 決定

1. **体験の使用状況の規則は domain の `entitlement::TrialUsage` の 1 か所に置く**。材料は、月額の受講権（動画とチャットの送り放題）・キャンセルされていない予約・完了したレッスン（同期・非同期）・送った動画（添削待ちも返却済みも含む）の有無
   - 体験予約できる（`is_trial_available`）: どの材料もないときだけ。月額契約の生徒は体験の対象でない
   - 動画の添削を依頼できる（`may_request_video_review`）: 月額の受講権があれば常に。なければ完了したレッスンも送った動画もないときだけ（体験として 1 本）
   - `Booking::is_trial_available` は予約の有無を自分の予約から決め、残りをこの規則に任せる
2. **材料は application の 1 つの照会（`entitlement::TrialUsageLookup`、実装は `EntitlementTrialUsageLookup`）でそろえる**。体験予約の作成（`CreateBooking`）・自分の予約の一覧の `trial_available`（`ListMyBookings`）・動画の送付の門（`EntitlementVideoReviewGate`）が同じ照会を使う。予約の有無は照会に載せず、呼ぶ側が持つ予約（体験予約の作成は、保存するトランザクションの中で読んだ予約）から足す
3. **動画の送付（`SubmitVideo`）は、メッセージの `ChatGate` と同じ形のポート `async_lesson::VideoReviewGate` に問い合わせる**。断られたら何も保存せずイベントも出さず、interface が 403 `video_review_not_entitled` に写す。アプリはこのとき月額契約への入口を出す
4. **まだ受けていない体験予約を動画の添削に切り替えるときは、送付の時点でその予約を生徒のキャンセルとして解放する**（scheduling の `CancelBooking`。枠が戻り、`BookingCancelled` と `booking.cancelled` も生徒のキャンセルと同じく出る）。体験予約でない予約は触らない
5. **アプリは `trial_available` だけで体験予約かどうかを決める**（予約の件数で数え直さない）

## 結果

- 体験の定義を変えるときは domain の `TrialUsage` の 1 か所を直せばよい。予約・一覧・送付が同じ規則で断られる
- 送付が断られうるので、生徒アプリは 403 `video_review_not_entitled` で月額契約への入口を出す（アプリ側は別のチケット）
- 既存データはさかのぼって触らない。体験を使い終えた後に送られた添削待ちの動画も、コーチは今までどおり返せる（返却の門 `ReviewGate` は変えない）
- 合成シードの計画には門ができる前の振る舞い（月額契約をせずに動画を送り続ける生徒）が含まれるので、シードの動画の送付だけは門を通さない（`FixedVideoReviewGate`）
- 体験予約・一覧・送付のたびに受講権・完了記録・動画の保存先を読む照会が増える（体験予約でない予約の作成は読まない）

## とらなかった案

- **アプリ側の判定を直すだけにする**: サーバーが受け付けてしまうので、別のクライアントや古い版から無料の添削が通り続ける
- **動画の送付にだけ別の判定を足す**: 予約・一覧・送付で定義がずれ、#1595・#1645 と同じ食い違いがまた起きる
- **体験予約の解放を境界間イベント（`VideoReviewRequested`）の購読で行う**: 購読の失敗は捨てられる（インメモリのイベントバス）ので、解放されないまま体験の通話も受けられる状態が残りうる。送付の門の中で同期に解放する
