# ADR 0014: 体験の定義を `trial_available` に一本化する

- 状態: 提案（工場）（2026-11-15、Issue #1659。親 #1653）
- 関係: ADR 0006（初回かどうかをアプリで数え直さず、サーバーの判定に従う）、ADR 0005（ビデオ通話の枠の消費）、ADR 0010（生徒の次の行動はサーバーの状態から出す）、`specs/contracts/api/student-app/openapi.yaml`（`listMyBookings` の `trial_available`、`createBooking` の 409 `trial_already_used`、`submitVideo` の 403 `video_review_not_entitled`。#1657）、`specs/stories/student-books-after-first-lesson.yaml`

## 文脈

体験（通話か動画添削のどちらか 1 回の無料のレッスン）を使ったかどうかを、生徒アプリが予約の件数から数え直していた時期があり、サーバーの判定とずれた。その結果、体験の通話を受け終えた月額契約の前の生徒が、そのあと無料で動画の添削も依頼できていた（#1653）。

#1657 で契約に、体験を使い終えた生徒の `submitVideo` を断る 403 `video_review_not_entitled` を足し、`trial_available` の判定に送った動画と月額契約を含めた。体験の判定はサーバーにあり、アプリの役目はそれに従うことと、断られた生徒を次の行動（月額契約）へ案内することになる。

## 決定

1. **体験予約できるかは `listMyBookings` の `trial_available` だけで決める**。予約の件数・キャンセルの有無・完了したレッスンや送った動画の件数からアプリで数え直さない。応答に載っていない（古いサーバー）ときは体験なし（通常の予約）として扱う
2. **自分の予約をまだ読めていなければ、読んでから決める**。スロットを探す画面を開いたとき・スポーツで絞ったとき・予約するときに、まだ読めていなければ `listMyBookings` を読む。読めない間は推測で予約を作らない（予約のボタンは押せない）
3. **断りはサーバーの 2 つの応答に従う**。体験予約は 409 `trial_already_used`（読んだ判定が古かった。予約を読み直して通常の予約に切り替える）、動画の添削の依頼は 403 `video_review_not_entitled`
4. **添削の依頼が 403 `video_review_not_entitled` で断られたら、月額契約へ進む入口を出す**。チャットの「添削を依頼する」とホームの「添削を依頼する」（担当コーチとのスレッドを開いて依頼する）の両方で、依頼のボタンのそばに「月額契約へ進む」を出す。押したら月額契約の画面へ進み、契約のあとは開いていたスレッドへ戻れる（チャットを送れなかったとき 403 `chat_not_entitled` と同じ扱い）

## 結果

- 体験の判定の置き場がサーバー 1 か所になり、アプリとサーバーがずれて無料のレッスンが 2 回通ることがなくなる
- 自分の予約を読めないときや古いサーバーの応答では体験なしとして扱うので、体験を使える生徒が通常の予約にしか進めないことがある（予約を読み直せば体験予約に戻る）
- 体験を使い終えた生徒が添削を頼もうとしたとき、断りの文言と一緒に月額契約への入口が出るので、そこで止まらずに続けられる
- 月額契約や決済の処理・画面は変えない

## とらなかった案

- **アプリで予約の件数から数え続ける**: サーバーの判定（送った動画・月額契約・受け終えた体験予約のキャンセルを含む）を書き写すことになり、条件が増えるたびにずれる。今回のずれ（#1653）がその例
- **添削の依頼の前にアプリで体験を使ったかを判定してボタンを隠す**: 判定をアプリに置くことになる（決定 1 に反する）。依頼してサーバーに断られてから案内する
